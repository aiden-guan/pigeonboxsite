Start with the extension

Local inbox triage, briefs, drafts and chat run while Gmail is open. Choose on-device AI, Ollama, or your own API endpoint and key. Local features need no PigeonBox account.

Install PigeonBox from source or a release.

Add your own server

The server adds background Gmail sync, prepared drafts, follow-ups, briefings, calendar help, tracking and tracked PDFs. Each feature becomes available when you configure its dependencies.

You need Cloudflare, a Supabase project, a Google Cloud OAuth client, and an AI provider with Chat Completions, tool calls, structured JSON and embeddings support.

cp server.env.example server.env
npm run server:deploy -- --dry-run
npm run server:deploy

Fill in your Supabase settings, AI endpoint, model and key, and allowed email addresses before deploying. The script applies the schema, deploys both Workers and points your extension build at them. Follow the complete self-hosting guide.

Connect Gmail when you need it

Use your own Supabase project for sign-in. ALLOWED_EMAILS controls who can use your server and spend its AI credits. Always-on Gmail additionally needs the Gmail and Calendar APIs and a Google Pub/Sub subscription.

Personal OAuth apps have Google consent and testing limits. Review those in the guide before inviting other people. Sending and other actions follow the permissions and approvals you configure.

Keep your keys and backups

Keep server.env and .local/server-secrets.json private. Back up the encryption keys: stored mail data and Google credentials need those same keys after an update or a move.

The software is MIT-licensed. You pay your infrastructure and AI provider directly. There is no PigeonBox subscription, hosted account or waitlist.
