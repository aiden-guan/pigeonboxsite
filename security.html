SECURITY ARCHITECTURE

Built with
clear boundaries.

Cloud sign-in, billing, and hosted processing are separate from Gmail’s page. The public extension documents its threat model and the data each mode handles.

SIGN-IN & ACCESS

Scoped to your account.

OAuth with PKCE starts sign-in. Gmail content scripts do not receive PigeonBox tokens. The server derives the account from a verified token rather than a client-supplied account ID. Hosted records use account scoping and Postgres row-level security.

BILLING & REQUESTS

Separate systems.

Stripe handles card details through Checkout and its customer portal. Webhooks are signature-verified and processed idempotently. Cloud AI request content is processed without being stored in PigeonBox Cloud’s database or logs.

Report a vulnerability

Please follow the private disclosure instructions in the public repository’s SECURITY.md. The threat model describes extension trust boundaries and known limits.

No certification or independent audit is claimed here.
